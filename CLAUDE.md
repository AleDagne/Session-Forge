# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Session Forge: Italian-language D&D 5e session planner/player (maps, characters, creatures, combat, exploration, dice). Pure HTML/CSS/vanilla JS — no build step, no package manager, no dependencies, works offline (PWA). All UI text, comments, identifiers in data and commit messages are in **Italian**; keep to that. `README.md` (long, ~890 lines) is the detailed feature/data-model reference; `RIPRESA-LAVORO.md` is a work-resume log of the last development phase.

## Commands

- Run: open `index.html` directly, or serve it (needed for PWA/service worker). `.claude/launch.json` defines the `session-forge` server: `python .claude/servi.py 5617` (like `http.server` but `Cache-Control: no-store`, so tests never run stale files) → `http://localhost:5617/index.html`.
- Tests: open `test.html` in a **visible** browser window (served, e.g. `http://localhost:5617/test.html`). It loads every script then runs `DnD.runTests()`; results are listed on the page with a pass/fail summary (hidden pane stays on "Esecuzione…"). There is no CLI runner: tests are registered with `test(name, fn)` in `js/test.js` (helpers `eq`, `ok`, `seq(...)` for deterministic dice); `DnD.runTests('part of name')` runs only matching tests (from the console; the page's own run still executes everything), and `DnD.testInCorso` names the running one. A hidden page throttles timers, so the async online tests become very slow there; a 0×0 viewport (hidden browser pane) makes the boss-vignette test fail (`elementFromPoint` returns null): give the tab a real size first. Safety-net tests: «Migrazione: l'archivio di esempio…» (compares `test/fixture/archivio-v18.json` normalised against `atteso-v18.json`), «Fumo: …» (loads `index.html?prova` in an iframe: in-memory store, no service worker; restores localStorage afterwards) and «Elenchi dei file» (index/test/sw lists aligned).
- Browsers cache scripts aggressively: hard reload (Ctrl+F5) after edits.
- No lint/build commands exist.

## Architecture

- **Classic scripts, one global namespace.** No ES modules: every file is an IIFE `(function (DnD) { 'use strict'; … })(globalThis.DnD = globalThis.DnD || {});` that attaches to `DnD.<module>`. Load order matters and is defined by the `<script>` list in `index.html`; **`test.html` duplicates that list** and `sw.js` has a third copy (`FILES`). When adding/renaming a script or CSS file, update all three.
- **Layering by file prefix/order** (in `index.html`): `config/dadi/regole/classi/magie…` (pure rules & data) → domain logic (`griglia`, `movimento`, `creature`, `boss`, `biomi`, `eventi`, `esplorazione`, `percorso`, `leggendario`, `ia`, …) → `validazione`/`dati`/`sessioni` (store, migrations, import/export) → `ui-*.js` (DOM) → `app.js` (boot, nav, sessions). Domain modules are pure/logic-only and unit-tested; `ui-*.js` build DOM via `DnD.ui.el(...)` (`ui-comune.js`) and are not covered by tests.
- **Nav/menu** is data-driven from `DnD.config.MENU` (`js/config.js`), each item with a fixed `key` for its Alt+key shortcut (digits, plus `S` for Scene); `APP_NAME` is also in `config.js` (and `manifest.json` by hand).
- **Data & persistence** (`js/dati.js`, `sessioni.js`): data model is versioned (currently **v18**) with chained migrations `migrateV8 … migrateV12` (v13–v18 only need normalization; v18 = grid `vision`/`fog` (light, sight cells, rooms, fog modes), combatant `senses`/`light`; v17 = player `sheet`, `backgrounds`/`feats` libraries; v16 = scenes/encounters, players `xp`: string conditions become entries, sheets get a `status` for rests, standard enemies get `crOverride` and bosses `boss.effectiveCr`) run on raw data, including imported files. Data is per-origin (file:// vs localhost differ). Per-session data (npcs, players, grids, combat, exploration, notes, and the Mondo: factions, parties, cities, worldNpcs, quests, `session.world`) vs global libraries (races, spells, structures, equipment, mapObjects, tilesets, biomes, events, pathTemplates) — items can be flagged shared across sessions. Large images/tilesets live in IndexedDB (`immagini.js`). Changing the schema ⇒ add a migration, bump version, update README "Modello dati".
- **Dice**: `dadi.js` uses rejection-sampled `crypto.getRandomValues`; roll functions take an injectable RNG (tests pass `seq(...)`). `dadi.registratore` annotates rolls for the animated-dice overlay (`ui-dadi.js`, `css/dadi.css`) without changing results.
- **Combat/entities**: combatants are built by `combattenti.createCombatants` (`js/combattenti.js`, above the pure 5e rules in `regole.js`); creatures, bosses (phases/themes in `boss.js`) and legendary players (`percorso.js` skill-graph + `leggendario.js` effects/transformations) all reduce to the same creature-style action model so combat UI, IA (`ia.js`) and `movimento.js` (speeds, path costs, per-turn residual) treat them uniformly. Legendary themes reuse the boss theming system via `lg:<id>` keys; colours come only from CSS variables (`--boss-*`, `--lg-*`), never hard-coded in components.
- **Mondo** (`dati/mondo` data → pure `fazioni`/`party`/`citta`/`npc`/`quest` → `ui-mondo`/`ui-party`/`ui-npc`/`ui-quest`): `DnD.fazioni.relazione(a, b)` / `relazioneCombattenti` is the single source of truth for hostility (IA, movement, area warnings, combat end, NPC provocation); the three builtin factions `giocatori`/`nemici`/`neutrali` keep the old combat sides' ids. Placed NPC copies are map objects with `otype: 'npc'` and their own `npcState`.
- **Conditions** (`condizioni.js` pure → `ui-condizioni.js`): combatant `conditions` are entries `{ type, source, duration, spellId, … }`; attack/save/check/speed/action code reads modifiers from `DnD.condizioni` (`attackMods`, `saveMods`, `checkMods`, `speedEffects`, `actionBlock`) instead of hard-coding condition names. Concentration, death saves and turn-based durations live there too; `ui-combattimento.js` applies them in `hurt()`, `conditionsAfter()` (inside `mutate`) and `nextTurn`/`startTurnOf`.
- **Rests/resources** (`dati/riposi.js` data → `riposi.js` pure → `ui-riposi.js`): a «subject» of accessors (`fromSheet(player, st, explorationMember?)` or `fromCombatant(c)`) unifies hit dice, HP/temp HP, exhaustion, slots, legendary/creature uses and custom resources; `shortRest`/`longRest`/`restoreAll`/`dawn` work only on subjects. Player sheets keep a persistent `status` (current HP, temp HP, hit dice used, exhaustion, last long rest, custom resources) seeded into combatants (`seedCombatant`) and written back at combat end (`syncBack`); exploration rests go through `esplorazione.rest` (hour by hour, encounters interrupt).
- **Encounter difficulty** (`dati/difficolta.js` tables → `difficolta.js` pure → `ui-difficolta.js`): DMG thresholds/multipliers, `crOf` (creature cr, boss `effectiveCr`, standard `crOverride` or level/2), `counts` uses `fazioni` hostility; house rules live in state `difficultyRules` (global, exported with the archive). Indicator used by combat setup, generator, exploration encounters; Budget in creature/boss sheets.
- **Scenes** (`dati/scene.js` → `scene.js` pure → `ui-scene.js`, menu item first with Alt+S): per-session `scenes` (ordered, links by outcome, embedded encounter copies with `run` state) and the `encounters` library (models); `buildCombat`/`buildExploration` launch them, `combat.scene` links a combat back so `ui-combattimento` hands the end to `DnD.uiScene.onCombatEnded`. `DnD.scene.remap` must run whenever sessions are duplicated/imported.
- **Player sheet** (`dati/scheda.js` → `scheda.js` pure → `ui-scheda.js`): players are created/edited on a paged sheet (wizard / sheet / game view, print) working on a draft; `ui-creature.renderForm` delegates players to `DnD.uiScheda.editor` (enemies keep the old form). `combattenti.derivedStats` applies feat effects and the sheet's initiative/speed overrides; `leggendario.checkBonus` reads skills via `scheda.skillBonus`; `riposi.seedCombatant`/`syncBack` carry sheet conditions and death saves.
- Use `DnD.ui.fill(node, ...children)` (not native `append`) when children may be `null` or arrays.
- **Sounds**: everything goes through `DnD.audio.suona(id)`; events and recipes are data in `dati/suoni.js` (synthesised, no files).
- **Light, vision, fog of war** (`dati/visione.js` → `visione.js` pure → `ui-visione.js`): every grid has `vision` (ambient light, placed sources, per-cell sight overrides, rooms) and `fog` (mode manuale/auto/mista, `seen` = explored memory, `manual` master touches, ghosts); the exploration discovery fog is the same `fog` (`esplorazione.discoveryView`/`reveal` use it). `DnD.visione.context(grid, combatants)` builds sight map + light map; `canSee` is the single source of truth for who sees whom (used by `ia.visible`, attack mods via `condizioni.attackMods({ vision })`, players' fog, `visioneGiocatore()`). Sight blocking is separate from movement blocking (`blocksSight` on structures/objects, closed doors, blocking tiles). The grid component takes `opts.vision` (a `uiVisione.create` controller: cached offscreen layers, painter tools, panel, «Vedi come»); after changes the combat calls `visionAfter` (prune concentration-linked lights, `refreshFog`).
- **Online play** (`js/rete/`: `protocollo` → `trasporto` → `codici` → `segnalazione` → `filtro` → `immagini` → `sessione`, pure/testable except the WebRTC parts of `segnalazione`/`trasporto.daCanale`; DOM in `ui-online.js`): an abstract text transport (WebRTC DataChannel or `coppiaMemoria` for tests) carries versioned JSON messages validated on receipt (`protocollo.decodifica`, direction, schema, size, rate limit). Manual signalling: invite/answer codes (compressed, 5 minutes, single use). The master filters on its side: `filtro.istantanea(state, opts)` builds the player view (never hidden combatants/objects, notes, unrevealed bosses, AI log lines, enemy exact HP), `filtro.differenze`/`applica` make numbered incremental events; `sessione.master/giocatore` handle approval, kick, re-entry, chat, shared dice, chunked images (by content hash, IndexedDB on the player), heartbeat. `DnD.store.onChange` triggers `master.aggiorna()`; the player screen uses `uiGriglia.create({ readOnly, tilesets, canDrag, movement })` and `DnD.app.show` is blocked while `uiOnline.vistaGiocatore()`. Stage 2 (protocol v2): players send intentions only; `rete/intenzioni.js` (pure) has the schemas, permissions, per-turn action economy, checks (`verificaMovimento` via `movimento.walk`, `verificaAttacco`, `verificaMagia`, sheet deltas), and the violation register; `sessione.master` validates and then executes through `DnD.uiCombattimento.online` (the same `performAttack`/`performCast`/`movementApply`/`performSave`/`nextTurn` as the master's buttons, returning `{ ok, testo, tiro }`; `dadiDiProva(rng)` makes tests deterministic). Permissions, manual-confirmation queue, return tokens, economy and register live only in the master's memory.
- **Grid/maps**: `griglia.js` is the grid model; blocking is centralised in `DnD.griglia.isCellBlocked` (structures, closed doors/blocking map objects, forced cells, blocking tiles from `tilemap`/`tileset`). Grids are `battaglia` or `esplorazione` (biomes, events, fog).
- **Theming/settings**: `impostazioni.js` loads first (before CSS paint) to set theme/text size/reduced motion; all colours are CSS variables in `css/style.css`. Respect "Riduci animazioni" and "Effetti boss" settings in any new animation.

## Conventions

- Match the existing style: 2-space indent, single quotes, `const`/arrow functions, short Italian comments describing intent.
- After modifying any cached file, bump `CACHE` in `sw.js` (currently `session-forge-v53`).
- New logic should get tests in `js/test.js` and a README update (features, data model, migration notes, "Struttura" file list).
